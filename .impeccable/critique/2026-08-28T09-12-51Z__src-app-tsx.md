## Overall Impression

The populated wall and the 翻牌 object are the product. The first frame is not. An empty 1200×800 cabinet greets the owner with `没有匹配的卡片。`, `0 shown`, an umber write FAB, and a stack-trace toast if they press 同步 without a Key. `get_setup_status` already exists in Rust and is never asked. The single biggest opportunity is to make day-zero and “find this line” tell the truth: one setup sentence, one honest search mode, one un-truncated drawer.

## Priority Issues

### [P1] First-run empty state is a filter miss, not a setup
- **What:** `.empty-state` = `没有匹配的卡片。` Header = `0 shown`. `.fab` is the primary empty affordance. Backend `get_setup_status` (`hasKey`, `hasBooks`) is dead. 同步 on a machine with no Key toasts a stack trace.
- **Why it matters:** The first job is Key → 同步 → wall. Day-zero never gets that sentence. PRODUCT success (“daily open”) dies before a card exists.
- **Fix:** If `!hasKey || !hasBooks`, replace the void with one instruction + one umber button (“粘贴微信读书 API Key” → 设置, or inline the field). Disable 同步 until `hasKey`. Map IPC errors to Chinese. Use “没有匹配” only when a filter/search is actually on.
- **Suggested command:** `/impeccable onboard`

### [P1] Search pretends to be in the current drawer and is not
- **What:** `search_cards` always sends `emptyFilter()`. When `activeBook` is set, `.content-header` still shows that book’s cover, title, and 划线/想法 chips. Sidebar keeps the book `.active`. The `Search / 搜索结果` eyebrow only appears when *no* book is selected.
- **Why it matters:** The returning reader who clicked 活着 then typed a phrase is told they are still in 活着. Results are library-wide. They will “fix” the wrong filter.
- **Fix:** Search is a mode: force the search eyebrow even with a book selected; dim or clear book/tag/star chrome; or actually pass the current filter into `search_cards`. Esc already clears the query — pair it with a visible “正在搜全部卡片”.
- **Suggested command:** `/impeccable clarify`

### [P1] Card wall silently stops at 500
- **What:** `query_cards({ limit: 500, offset: 0 })`. `{cards.length} shown` will read `500 shown` with no “还有”.
- **Why it matters:** The months-later find-by-scan path is a stated success criterion. Old highlights fall off the cabinet with no drawer label.
- **Fix:** Show `已显示 500 / 共 N` and a “继续载入”, or virtualize. Search remains the fast path — say so when truncated.
- **Suggested command:** `/impeccable harden`

### [P2] Daily 翻牌 cannot 补写想法, and it is not a stage
- **What:** `ReviewView` is read-only flip → silent `grade_review('good')`. No pen, no undo, no Again. `.topbar` search and 同步 stay. Copy says `轻触翻面` on a desk app.
- **Why it matters:** Primary loop is scan / filter / flip / add thought. Thought is only behind hover `pen` on the wall. Flip-is-Good with no undo turns a quiet ritual into a one-way bet. Competing chrome keeps the desk noisy.
- **Fix:** One ghost “记下想法” on the front face (opens `EditModal`). Optional: Z / Esc-back to undo last Good. Hide search/同步 or collapse `.sidebar` while `view.name === 'review'`. Say `点击或空格翻面`.
- **Suggested command:** `/impeccable distill`

### [P2] Chrome inconsistencies that tax a “可信” brand
- **What:** Create `保存` is a default button; Edit `保存` is `.primary`. Empty Create `return`s with no message. Gear does not toggle off 设置 (leave via 全部卡片, losing book context). 同步 in `.topbar` and 立即同步 in 设置. `.search input:focus { outline: none }` (and modal/settings inputs) kill the ember focus ring. `Cover` `alt=""`.
- **Why it matters:** Small lies add up. Keyboard users lose the one focus language the CSS promised.
- **Fix:** Primary on Create; disable/err empty save; gear toggles back to last cards view; one sync control; drop the `outline: none`; give header Cover a real `alt={title}`.
- **Suggested command:** `/impeccable polish`

## Minor Observations

- Starred highlights do not get `--ember-wash` despite DESIGN `card-starred`; they only get `::after` ★.
- `.card.expanded` unclamps `.card-text` only; `.card-note` stays 2-line clamp.
- `.card-note` and `.abstract blockquote` still use a 1px left rule — legal vs the 2px-color-bar ban, leftover stripe the spec warned about.
- Chip `text-transform: uppercase` is a no-op on 中文 tags.
- `fmtDate` is catalog-correct; header `shown` should have been `张`.
- Logo `.mark` is Lucide `layers`, not `design/logo/logo-mark.svg`.
- Settings `h3` “微信读书 API KEY” + `text-transform: uppercase` on dialog titles (`新建卡片`, `确认`).
- Window min 900×600; `@media (max-width: 1100px)` drops the wall to 2 columns. Tags `max-height: 140px` leaves a tall empty `.side-scroll` when the shelf is empty.
- Toast `role="status"` is correct; 2600ms of `TypeError` is not.
- Hover-only `.card-actions` do reveal on `:focus-within` — keyboard can reach them if tabbed, but they are undiscoverable without hover or focus.
