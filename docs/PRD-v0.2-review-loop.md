# 泥滩知识 v0.2 PRD：会记事的翻牌

- 版本主题：从"收进来"到"记得住"
- 状态：Draft for review
- 建议周期：2 周开发 + 1 周灰度
- 产品形态：macOS 本地优先桌面应用（Tauri 2 + React + SQLite）

## 1. 背景与核心判断

v0.1 已具备微信读书同步、本地卡片库、全文搜索、书籍/标签/星标筛选、补写想法、自建卡及简化 SM-2 回顾。下一版本不应继续扩内容源，而应修好核心闭环：**新内容可靠进来；用户能持续回来回顾，并控制自己回顾什么。**

### 1.1 当前关键问题

| 问题 | 用户影响 | 代码现状 |
|---|---|---|
| 增量同步失效 | 首次同步后新增划线/想法可能不再进入本地 | `run_sync` 先用远端计数覆盖本地，`needs_pull` 再比较两者，已有 `synced_at` 的书恒不拉取 |
| 所有新卡立即到期 | 首次同步数百条后产生巨大债务感 | 新卡创建即写 `review_state(due_at=now)` |
| 回顾只能"记得" | 用户无法反馈遗忘，SRS 退化为一次性抽卡 | 后端四档齐全，前端写死 `rating:'good'` |
| 无法治理队列 | 低价值摘录长期占据回顾 | `excluded_from_review` 与按书开关后端存在，UI 未接线 |
| 一批结束不等于今日完成 | 总数大于 30 时完成反馈不可信 | 固定取 30 张，结算不重查剩余 |
| 同步卡删除后会复活 | "不可撤销"文案与实际行为冲突 | 软删后 upsert 重置 `deleted=0`，测试锁定复活为预期 |
| 无数据库迁移框架 | 任何 schema 变更都可能破坏旧库 | 仅 `CREATE TABLE IF NOT EXISTS`，无 `user_version` |

### 1.2 版本机会

> 用户可以选择值得记住的内容，真实反馈记忆程度，看到明确的下次回顾安排，并在有限批次内获得可信的完成感。

## 2. 用户与场景

**核心用户**：已有 100–5000 条微信读书划线、愿意每天投入 5–10 分钟、但不想维护复杂卡组的中文长文读者。重读轻写：内容生成发生在微信读书，这里负责"重新遇到并消化它"。

核心任务：

1. 新划线和想法能可靠同步进来；
2. 只回顾真正重要的内容；
3. 按真实记忆情况调整再次出现时间；
4. 每次完成可承受的小批次，并知道今天还剩多少；
5. 相信系统的同步、删除与回顾反馈。

## 3. 目标与非目标

### 3.1 版本目标

1. **数据可靠**：修复增量同步，建立升级迁移；
2. **评分有效**：四档记忆反馈进入主流程；
3. **范围可控**：卡片可移出/恢复回顾；
4. **负担可控**：明确小批次与真实剩余数；
5. **行为可信**：同步卡隐藏后不再静默复活。

### 3.2 非目标

本版本明确不做：

- 新增微信读书之外的导入源；
- AI 摘要、AI 问答或自动制卡；
- 账号体系与云同步；
- 移动端；
- 完整卡组/文件夹系统；
- 用 FSRS 等替换现有简化 SM-2；
- 大规模视觉重设计（继续遵循 DESIGN.md「刊物排印」规范）。

## 4. 成功指标

**北极星：周有效回顾用户数（WERU）**——7 天内至少完成 2 次回顾、累计评分不少于 20 张的用户数。

| 指标 | 定义 | 目标 |
|---|---|---|
| 同步正确率 | 远端新增/删除在下一次同步正确反映 | 100% |
| 首批完成率 | 开始首批后完成该批的用户占比 | ≥60% |
| 7 日二次回顾率 | 首次完成后 7 天内再完成一批 | ≥35% |
| 非 Good 评分率 | Again/Hard/Easy 占全部评分 | ≥20% |
| 队列治理率 | 使用过"移出回顾"的完成用户占比 | ≥25% |
| 错误完成反馈 | 尚有到期卡却显示"今日完成"的次数 | 0 |

坚持纯本地、无遥测时，只在本机保存回顾开始、评分、批次完成、移出、恢复五类匿名行为计数与时间，不记录正文、书名、标签。

## 5. P0 需求（必须交付）

### R0 增量同步正确性与迁移框架

**用户故事**：再次点击同步后，新划线、新想法和远端删除能可靠反映到本地。

**需求**

1. 按书持久化"上次成功内容同步"的划线数和想法数（与远端最新计数分开存）；
2. 用本次远端计数与该成功基线比较决定是否拉取，不能先覆盖再判断；
3. 单书内容事务成功后才更新该书基线；失败书不更新，下一次同步重试；
4. 建立 `PRAGMA user_version` 幂等迁移机制，支持 v0.1 真实旧库升级；
5. 升级前自动备份数据库，迁移失败不得覆盖原库；
6. 同步总结显示成功书数、失败书数、新增/移除卡数；单书失败不阻断其他书。

**验收标准**

- 首次同步后远端新增划线/想法，再次同步可见；
- 远端删除后本地正确软删，不误伤用户编辑（note/星标/标签保留）；
- 失败书下次同步仍会重试，成功书不受影响；
- v0.1 旧库升级后卡片、标签、批注、星标、排除状态、SRS 状态全部保留；
- 迁移失败时保留原数据库并阻止启动覆盖。

### R1 四档记忆评分

**用户故事**：回顾时选择"忘了 / 困难 / 记得 / 简单"，让系统按真实记忆程度安排下次回顾。

**交互要求**

1. 未翻面不展示评分；翻面后展示 `1 忘了`、`2 困难`、`3 记得`、`4 简单`；
2. 数字键 1–4 与点击行为一致；空格/Enter 只负责翻面，不再自动提交 Good；
3. 每张只提交一次，评分请求与飞出动画期间禁重复操作；
4. 成功后短暂展示下次到期："10 分钟后""明天""3 天后"等；
5. 失败时停留当前卡，进度不递增，可重试。

**验收标准**

- 新卡四档按现有调度器分别得到约 10 分钟、1 天、1 天、3 天；
- 未翻面按数字键不提交；
- 请求失败当前卡与序号不变；
- 鼠标与纯键盘均可完成全流程；
- 四档均有 Rust 调度测试与前端交互测试。

### R2 单卡回顾范围控制

**用户故事**：把低价值卡片移出回顾，但仍能在卡片墙和搜索中找到它。

**需求**

1. 卡片编辑弹层增加 `纳入翻牌回顾` 开关；回顾正面增加 `移出回顾` 次级动作；
2. 移出后卡片继续保留在卡片墙、书籍、标签和搜索结果中，但不再进入到期队列；
3. 卡片墙显示低强调度状态"已移出回顾"；
4. 可从编辑弹层重新纳入，恢复后立即进入待回顾状态；
5. 同步不得覆盖用户的排除状态。

**验收标准**

- 队列中的卡移出后当前批次进入下一张，全局到期数减 1；
- 被移出的卡仍可搜索命中；
- 恢复后 `excludedFromReview=false` 且进入到期队列；
- upsert 与 reconcile 均不重置该字段。

### R3 可信批次与完成状态

**用户故事**：每次只完成一个明确的小批次，并知道今天是否还有到期内容。

**需求**

1. 默认每批 20 张；设置提供 10/20/30 三档，本地持久化；
2. 进入前展示 `今日到期 N 张 · 本批 M 张`；回顾中同时展示本批剩余、今日总剩余；
3. 批次完成后重新查询真实到期数：为 0 显示"今天翻完了"；大于 0 显示"本批完成，今天还剩 N 张"，主按钮"继续下一批"，次按钮"返回卡片墙"；
4. 只把成功评分计为完成；移出回顾单独计为已处理；失败不计数。

**验收标准**

- 到期 45 张、批次 20，首批结束显示还剩 25 而非"全部完成"；
- 到期 8 张、批次 20，完成后显示"今天翻完了"；
- 评分失败不增加完成数；
- 批次设置重启后仍生效。

### R4 删除语义可信化

**产品决策**：同步卡的删除必须是用户持久决策，不能在下次同步静默复活。

**需求**

1. 自建卡物理删除，确认文案：`永久删除这张自建卡？此操作不可撤销。`；
2. 同步卡采用独立的"用户本地隐藏"墓碑，与"远端 reconcile 删除"分开；确认文案：`从泥滩知识中隐藏这张卡片？之后同步也不会恢复。`；
3. 同步 upsert 尊重用户隐藏墓碑，不重置为可见；
4. v0.2 不做回收站；
5. 若本版本无法安全实现墓碑，则取消同步卡删除入口，降级为"移出回顾"，不得保留错误承诺。

**验收标准**

- 同步卡隐藏后再次全量同步（远端仍存在），卡片不出现在墙、搜索与回顾中；
- 自建卡删除同时清理标签关联与回顾状态；
- 所有确认文案与真实数据行为一致；
- 修改/新增相应数据库行为测试。

## 6. P1 需求（有余力交付）

1. **每日新卡上限**：默认 20，仅限制首次曝光，不限制已学习到期卡；解决首同步整库到期。"新卡"锚定首次写入 `review_state`，避免复活/重同步击穿上限；到期徽标可显示"复习 X + 新卡 Y"。
2. **按书控制参与回顾**：书籍详情增加"本书参与回顾"；关闭只影响回顾队列，不停止同步。不直接复用语义耦合的 `sync_reviews`，拆分 `review_enabled` 与独立同步策略；关闭保留单卡调度状态。
3. **搜索继承上下文**：书籍、星标、标签范围内默认只搜当前范围并明示范围，可一键"搜索全部卡片"；复用现有 `search_cards(q, filter)`，前端把 `wallFilter()` 传入即可。
4. **本地回顾统计**：结算页展示本批四档分布；设置页展示近 7 天完成批次、评分张数、连续回顾天数；只存行为元数据。

## 7. P2 候选（后续版本）

Markdown/JSON 导出与数据目录快捷打开（备份焦虑）、按标签临时回顾集、首次同步"精选回顾"引导（星标/带想法优先）、想法→同段划线回链、章节分组浏览、kind 筛选 chips、AI 问题面、回收站与撤销、跨设备同步、FSRS。

## 8. 关键流程

1. **同步**：拉书目 → 与每书上一次成功基线比较 → 逐书拉内容并事务提交 → 更新成功书基线 → 汇总成功/失败/移除。
2. **回顾**：读取今日到期总数与批次设置 → 翻面 → 四档评分 → 等待返回 `SrsState` → 展示下次到期 → 下一张。
3. **移出回顾**：回顾正面或编辑弹层操作 → 首次说明"卡片仍保留在墙上" → 退出当前批次 → 可恢复。
4. **批次结算**：最后一张处理成功 → 重查 `get_due_count` → 展示本批处理数与四档分布 → 继续下一批或今日完成 → 返回卡片墙刷新侧栏到期数。

## 9. 信息架构与文案

继续沿用"刊物排印"视觉（DESIGN.md），不新增一级导航：

- 侧栏"翻牌回顾"保持常驻；
- 回顾页新增四档评分栏与"移出回顾"；
- 卡片编辑弹层新增"纳入翻牌回顾"开关；
- 设置新增"三、回顾"（批次大小），原"关于"顺延为"四、关于"；
- 用户文案使用"忘了 / 困难 / 记得 / 简单"，Again 等英文仅作内部枚举；
- 翻面后引导语："按你此刻的熟悉程度选择"。

## 10. 数据与技术要求

### 10.1 可直接复用

- `Rating` 四档枚举与 `schedule()`（srs.rs）；
- 返回 `SrsState` 的 `grade_review`；
- `excluded_from_review` 字段与 `set_excluded_from_review` 命令；
- `get_due_count`、`get_due_cards(limit)`；
- 带过滤参数的 `search_cards(q, filter)`。

### 10.2 需新增/调整

1. 每书"上次成功同步计数"（新列或 `sync_meta` 键）；
2. `user_version` 迁移 + 升级前备份；
3. 用户隐藏墓碑（与 `deleted` 远端删除语义分离）；
4. 批次大小设置（复用 `sync_meta` 或新增 `app_settings`）；
5. P1：`sync_reviews` 拆分为 `review_enabled` 与同步策略；
6. 同步失败清单进 `SyncSummary`；
7. 保持"不跨 await 持 SQLite 锁"的现有并发纪律。

### 10.3 数据迁移

- 所有 schema 变更走幂等迁移，不能只改 `CREATE TABLE IF NOT EXISTS`；
- 旧库升级保留排除状态与调度状态，批次默认 20；
- 存量软删同步卡无法区分用户删除/远端删除时，默认保持隐藏，避免内容意外复活；
- 升级前备份原库，失败不得覆盖。

## 11. 边界与异常

1. 连续评分只接受第一次请求；
2. 已成功评分立即落库；未评分的当前卡下次仍出现；
3. 同步完成不重置当前批次，下一批再读取新到期数据；
4. 单书同步失败不阻断其他书，失败清单可见；
5. 长文本正文独立滚动，评分栏固定可见；
6. 异常/空卡不阻塞整批，可移出回顾；
7. 无网络时除同步外，查看、搜索、编辑、回顾均可用；
8. FTS 查询输入需转义（P1 顺带），避免语法字符导致报错。

## 12. 测试与验收计划

### 12.1 自动化

- Rust 单测：四档调度、同步基线判断、排除/恢复、持久隐藏、迁移幂等；
- SQLite 行为测试：v0.1 旧库升级、再次同步新增/删除、隐藏卡不复活、批次与总数一致；
- 前端交互测试：翻面前禁评分、1–4 快捷键、失败不前进、结算分支；
- 构建验证：`npm run build`、`cargo test`、Tauri bundle smoke test。

### 12.2 手工验收矩阵

- 新库 / v0.1 旧库升级；
- 8、20、45、1000 张到期卡；
- 纯自建 / 纯同步 / 混合卡；
- 无网络、Key 过期、单书失败、同步中回顾；
- 鼠标全流程与键盘全流程；
- `prefers-reduced-motion`；
- 900×600 最小窗口与 1200×800 默认窗口。

## 13. 发布计划

### 阶段 A：内部验证（2–3 天）

- 使用复制的 v0.1 真实旧库与 500–5000 张大库；
- 重点验证：再次同步正确性、旧库升级、大量 reconcile、四档键盘效率、隐藏不复活；
- 退出条件：P0 全部通过且无数据丢失。

### 阶段 B：小范围灰度（7 天）

- 5–20 名已有微信读书笔记的用户；
- 每人至少同步两次、完成两批回顾；
- 收集：四档是否易懂、批次长度、是否需要按书控制。

### 阶段 C：正式发布

- 发布说明聚焦四件事：同步恢复可靠、四档记忆反馈、可移出回顾、可信小批次；
- 升级前自动备份；迁移失败保留原库。

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 修复同步后首次拉取触发大量 reconcile，卡片批量消失 | 高 | 升级备份、真实旧库预演、汇总并在结果中说明移除数 |
| 上游接口非公开且单书失败会中止同步 | 高 | 逐书容错、失败清单、下次重试 |
| 历史卡全部立即到期，压迫感仍强 | 高 | P0 小批次+范围控制；P1 新卡上限 |
| 墓碑迁移不当导致复活或丢失 | 高 | 用户隐藏与远端删除分列，专项回归测试 |
| `sync_reviews` 语义耦合 | 高 | P0 不暴露按书开关；P1 拆字段 |
| Hard 与 Good 新卡首轮都约 1 天，差异不明显 | 中 | 如实显示时间；本版不改算法 |
| 无遥测难判断效果 | 中 | 本地匿名计数 + 灰度访谈 |

## 15. 版本取舍结论

v0.2 的核心不是更多功能，而是兑现两项产品承诺：**新内容可靠进来；翻牌真正影响记忆计划，且用户决定什么值得反复出现。**

优先级不可倒置：

> 同步正确性与迁移 → 四档评分 → 单卡移出/恢复 → 可信批次 → 删除可信化 → 新卡上限、按书控制、上下文搜索与统计。

只有 P0 全部完成且旧库升级安全，v0.2 才具备发布条件。
