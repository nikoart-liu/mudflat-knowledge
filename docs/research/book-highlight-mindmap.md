# 按书划线生成脑图：方案

> 一句话：脑图上只放 AI 压缩后的概要节点，不把每条划线铺成叶子。划线是加工原料和可展开的证据；资料不够就画浅，不允许用全书常识补枝。

配套原则见 [`AI-feature-opportunity.md`](./AI-feature-opportunity.md)。Gemini Notebook 把 mind map 列为学习材料再生产的一种产物，但本产品没有全书正文，只能基于本地划线、想法与批注。

## 1. 要解决的问题

书内卡片墙已经按章节排开，用户能「顺着书翻」，却很难一眼看到：

- 自己到底划了哪几条主线；
- 不同章节是否在重复同一个概念；
- 哪些划线只是金句、哪些已经有自己的想法。

脑图的价值是**压缩与连接**：把几十到几百条划线收成一张可扫的结构图。默认画面里不应出现「N 张卡 = N 个叶子」。

## 2. 产品定义

AI 的工作是**概要加工**，不是搬运原文。

```text
全部划线（原料，不直接上图）
        │
        ▼
   聚类 / 归纳 / 命名
        │
        ▼
   概要节点树（画面上只看到这些）
        │
        └─ 每个节点背后挂着 2–N 张证据卡
           点击节点 → 侧栏或浮层看原文
           需要时才「展开证据」，仍不是默认叶子
```

| 是 | 不是 |
|---|---|
| 「我的划线被归纳后的脑图」 | 「全书知识图谱」或「划线墙的树形版」 |
| 画面节点 = 主题 / 子题 / 分歧 的短概要 | 每条划线占一个叶子 |
| 每条概要都能展开到支撑它的原卡 | 只能看不能核验的装饰图 |
| 可缓存、可重生成、可丢掉 | 静默写入卡片正文或标签 |
| 入口在当前刊物头 | 新开「AI」一级页 |

两种投影，画面上都是概要节点：

1. **章节骨架**：书 → 章名（真实）→ 本章 2–5 个概要。章名不当成 AI 创作。
2. **主题骨架（默认）**：书 → 5–12 个一级概要 → 可选 0–3 个二级概要。跨章合并同义、保留分歧。

证据永远在节点属性里，不在默认树结构里。一张 200 条划线的书，画面上大约 8–20 个节点，而不是 200 个。

## 3. 输入：一本书里真正能用的数据

从本地 SQLite 取 `deleted=0 AND book_id=?` 的卡，字段已经够用：

| 字段 | 脑图用途 |
|---|---|
| `id` | 证据溯源，点击回跳；不是默认节点 |
| `kind` | 划线 / 想法 / 自建卡 视觉权重不同 |
| `chapterUid` / `chapterTitle` | 第一层骨架；缺章归「未分章」 |
| `text` | 划线原文，叶子标题的来源 |
| `abstractText` | 想法卡对应的原文 |
| `note` | 用户自己的消化，权重大于纯划线 |
| `starred` | 优先进入主题中心 |
| `tags` | 可作为预置主题名，不强制 |
| `createdAt` / `rangeStr` | 章内排序，避免乱序簇 |

**默认纳入**：划线 + 该书下的想法。自建卡若 `book_id` 为空则不进书图。

**建议加权，而不是一视同仁**：

1. 有 `note` 或 `kind=thought` 的卡；
2. 星标卡；
3. 其余划线。

纯金句、过短（例如 <12 字）、无章无上下文的卡并入最近主题的证据，或进统计里的「未归入 N 张」，**不单独占一个概要节点**。

归纳粒度（硬限制，防止又画成划线树）：

- 全书一级概要 **5–12** 个；
- 每个一级下最多 **3** 个二级；
- 树深最多 **3**（书 / 一级 / 二级）；
- 每个概要至少 **2** 张证据卡才允许存在；只有 1 张则并入相邻概要或丢进未归入；
- 节点文案 **8–24 字**，是归纳句，不是划线截断。

## 4. 推荐管线

不要一上来把全书所有原文丢给模型。按库规模分三档。

```text
书内卡片
  │
  ├─ 过滤：未删除、未用户隐藏
  ├─ 章内排序（chapterUid → range/createdAt）
  └─ 内容哈希（所有卡 id+updatedAt）── 命中缓存则直接渲染
           │
           ├─ ≤80 张：一次结构化生成
           ├─ 81–400 张：按章生成再合并
           └─ >400 张：本地先聚类/抽样，再生成主题骨架
                       │
                       ▼
              结构化树 JSON（节点是概要，证据卡号挂在节点上）
                       │
                       ├─ 校验：所有 card_id 必须存在于本书
                       ├─ 校验：画面节点不得是单卡；空主题丢掉
                       ├─ 校验：节点文案不是某张卡原文的截断
                       └─ 渲染：默认只画概要；点开才看证据
```

### 4.1 小书：一次归纳

把每张卡压成一行喂给模型，但**要求输出的是概要树，不是卡列表**：

```text
#12 [章:习惯的复利] [划线] [星] 人不是拥有习惯，而是由习惯塑造。 | 注: 身份来自重复
#18 [章:习惯的复利] [想法] 关于身份的那段。 | 原文: ……
```

模型必须：合并同义划线、为每簇写一句 8–24 字概要、挂上卡号。禁止把某一行原文几乎原样当作节点名。

### 4.2 中书：按章归纳，再归纳一次

1. 每章生成 2–5 个概要节点 + 证据卡号 + 一句归纳；
2. 把各章概要（不含划线全文）再交给模型合并：同义合并、分歧保留、跨章主线升为一级；
3. 合并阶段只改概要节点，不得把卡号提升成画面节点。

这一档对 100–400 张卡最稳：单次上下文可控，输出规模被锁在「章数 × 2–5」。

### 4.3 大书：先本地压缩，再归纳

400 张以上不要全文进模型。

1. 用本地 embedding 或简单规则在章内聚类（过短/近重复合并）；
2. 每簇只送 1 条代表卡 + 簇内卡号列表 + 用户 note；
3. 星标和有想法的卡提高成为主题中心的权重，但**仍然不是叶子**；
4. 全书一级概要 5–12 个；每个节点默认展示最多 5 条证据，其余「还有 N 张」点开再看。

目标就是压缩：200 张划线 → 约 10 个可读节点。

## 5. 结构化输出（必须）

```json
{
  "bookId": 12,
  "title": "原子习惯",
  "mode": "chapter|theme",
  "inputHash": "sha256:…",
  "stats": { "cards": 128, "chapters": 9, "unplaced": 6 },
  "root": {
    "id": "root",
    "label": "原子习惯 · 我的划线",
    "kind": "book",
    "children": [
      {
        "id": "t-identity",
        "label": "身份由习惯塑造",
        "kind": "theme",
        "summary": "重复行为先改变身份，再改变结果。",
        "sourceCardIds": [12, 18, 44],
        "children": [
          {
            "id": "t-identity-repeat",
            "label": "重复行为改写自我叙事",
            "kind": "theme",
            "summary": "先变成那种人，再做出那种结果。",
            "sourceCardIds": [18, 44]
          }
        ]
      }
    ]
  },
  "warnings": ["有 6 张过短划线未放入主题"]
}
```

约束：

- 画面 `kind` 只允许 `book | chapter | theme`；`leftover` 只出现在 `stats` / `warnings`，不上图；
- **禁止 `kind: card` 作为树节点**。划线只存在于 `sourceCardIds`；
- `label` 8–24 字，必须是归纳，不得与任一证据卡 `text` 的前 24 字相同（后端做近似检测，命中则视为失败）；
- `summary` 可选，≤40 字，必须能被 `sourceCardIds` 支持；
- 每个 `theme` 至少 2 个合法 `sourceCardIds`，否则并入兄弟或丢进未归入；
- 模型不得输出不存在的卡号；后端丢弃非法 id 后若不足 2 张，删该节点；
- 不允许「作者生平 / 全书主旨 / 豆瓣评价」这类库外节点。

## 6. 提示词策略

系统提示只做三件事：聚类、写概要、挂证据。禁止把划线原文当作节点。

要点：

- 你看到的是用户划线，不是全书。没出现的论点不要补。
- 每个节点是一句归纳，不是摘录截断；读者应能不打开证据就看懂结构。
- 同一观点的多条划线必须合成一个节点。一条划线不能独占一个一级节点。
- 有 `note` 的卡提高该簇的命名权重，但节点文案仍是归纳，不是把 note 贴上去。
- 相互冲突的划线分成两个概要，或在同一一级下加「分歧」二级，不要抹平。
- 输出必须是给定 schema 的 JSON；树里没有 card 节点。

章节模式额外要求：第一层必须是真实章名，不得重命名章；章下仍是概要，不是划线列表。

主题模式额外要求：5–12 个一级概要；每个至少 2 张卡；二级可选且 ≤3。

## 7. 交互与视觉

入口放在当前刊物头，与「长读 / 翻牌」并列，文案用「脑图」或「线索」，不要用「AI 思维导图」。

建议交互：

1. 第一次生成前说明：将发送本书 N 张卡片的标题级文本（可展开看范围）；云模型默认关。
2. 生成中按章显示进度，单章失败不毁掉整图。
3. 画布默认只画概要：中心书名，周围 5–12 个一级节点，必要时再长出二级。节点上是归纳句，右下角用 mono 标「12」表示证据张数。
4. 点击节点不把树撑开成划线列表，而是打开证据抽屉：短摘、星标、想法、来源章节；再点一条才打开原卡。
5. 顶部切换「按章节 / 按主题」。章节模式下，章名是结构框，框内仍是概要。
6. 次级动作：复制为大纲（复制的是概要，不是原文）、用该节点的证据卡开始翻牌（后续版本）。
7. 缓存命中时直接打开；卡片有增删时显示「划线已变，可更新」，不自动覆盖用户正在看的图。

视觉必须服从刊物排印：直角、墨线、衬线只用于书名/概要。不要做成霓虹脑图、圆角气泡或 emoji。证据抽屉沿用现有卡片眉标（划线 / 想法 / 星标），但抽屉不是树的一部分。

## 8. 隐私、缓存与失败

- 范围锁定在**这一本书**，禁止顺手带上其他书「作为对比」——那是下一个功能。
- 调用前展示将发送的卡数、是否含 note、是否走云端。
- 缓存键：`bookId + mode + provider + promptVersion + inputHash`。
- 派生结果进 `ai_artifacts`（`artifact_type=mindmap`），不写回 `cards.text`。
- 用户可删除该图及其发送副本缓存。
- 模型超时/JSON 损坏：保留已成功的章节枝，标记失败章，允许重试。
- 离线且无本地模型：入口仍在，解释「需要本机模型或已缓存的图」。

## 9. 分阶段交付

### 阶段 0：无模型不要冒充脑图

章节分组已经在卡片墙里了，再画一棵「书 → 章 → 卡」的树没有增量，也违反「叶子不是划线」。阶段 0 只做入口、缓存位和证据抽屉的空态，不发布无 AI 的划线树。

### 阶段 1：章内概要（最小增量）

每章输出 2–5 个归纳节点 + 证据卡号。画面上章是框，框里是概要。这是最小 AI 增量，上下文小、幻觉面窄、可逐章重试。

### 阶段 2：跨章主题脑图（默认形态）

把各章概要再压缩成 5–12 个一级节点，可选二级。用户看到的就是这张图。

### 阶段 3：下钻与回顾

节点 → 证据抽屉 → 原卡 / 长读定位 / 临时翻牌集。大书走本地聚类后再归纳。未做语义检索底座时，大书路径不要提前做。

## 10. 验收

必须通过：

- 默认画面上没有单条划线节点；200 张卡的书，一级+二级节点合计 ≤ 36；
- 每个节点点开后能看到 ≥2 张真实证据卡，且都能打开原卡；
- 随机抽 10 个节点，人工判断「概要可被其证据支持」≥9，且概要不是某张卡的截断；
- 不出现库外人物、情节、结论；
- 隐藏卡、软删卡不出现在证据里；
- 新增 1 张划线后缓存失效提示出现，更新后该卡能进入某个节点的证据（或未归入计数 +1）；
- 200 张卡可在可接受时间内出图（章级并行，目标 <30s 本地小模型或 <15s 云端）。

明确失败形态：

- 划线树：节点数接近卡数，文案像摘录；
- 空心鸡汤：3–5 个大词，点开对不上原文；
- 为了对称补上用户没划过的部分。

## 11. 和既有 AI 优先级的关系

脑图属于第二梯队的「主题线索」，不是第一梯队。它适合作为**一本书内的主题线索可视化**，但：

- 没有 BYOK 网关就不要接云；
- 没有结构化输出校验就不要渲染；
- 若只能做一件 AI，仍应先做问题面或语义找卡——它们每天都会用。脑图是读完一本、想看结构时的低频动作。

若要做，正确切口是：**章内概要 → 跨章压缩成 5–12 个节点 → 点开看证据。** 任何一步只要把单条划线画成了树节点，就停。

## 12. 实例：《原子习惯》的 18 条划线 → 一张 7 节点脑图

假设用户在这本书里只划了 18 条（真实使用里常常是 80–300 条，压缩比会更大）。原料如下，**这些句子默认不上图**。

| id | 章 | 类型 | 原文 / 想法 |
|---|---|---|---|
| 1 | 习惯的复利 | 划线 | 人不是拥有习惯，而是由习惯塑造。 |
| 2 | 习惯的复利 | 想法 | 身份不是想出来的，是重复出来的。 |
| 3 | 习惯的复利 | 划线 | 每做一个 1% 的改进，你都在把自己变成那种人。 |
| 4 | 习惯的复利 | 划线 | 你高估了一天的意义，低估了两年的意义。 |
| 5 | 如何建立习惯 | 划线 | 让它显而易见、有吸引力、简便易行、令人愉悦。 |
| 6 | 如何建立习惯 | 划线 | 把新习惯叠在旧习惯后面。 |
| 7 | 如何建立习惯 | 注 | 我试过「早饭后立刻写 20 分钟」，比定闹钟有用。 |
| 8 | 环境 | 划线 | 环境是无形的手。 |
| 9 | 环境 | 划线 | 想多读书，就把书放在沙发上，把遥控器藏起来。 |
| 10 | 环境 | 星标 | 自控力是高估的，设计才是可重复的。 |
| 11 | 坏习惯 | 划线 | 让它看不见、没有吸引力、难以实行、令人不满。 |
| 12 | 坏习惯 | 划线 | 戒手机不是靠意志，是把充电器放到另一间房。 |
| 13 | 坏习惯 | 想法 | 和 #9 是同一件事的反面。 |
| 14 | 习惯的复利 | 划线 | 你的结果是滞后指标，身份才是先行指标。 |
| 15 | 如何建立习惯 | 划线 | 两分钟规则：入门必须短到不可能失败。 |
| 16 | 如何建立习惯 | 划线 | 先出现，再优化。 |
| 17 | 身份 | 划线 | 不要以结果为目标，要以身份为目标。 |
| 18 | 身份 | 划线 | 「我是跑步的人」比「我要跑完马拉松」更稳。 |

### 错误形态：划线树（不要做）

```text
原子习惯
 ├─ 人不是拥有习惯，而是由习惯塑造。
 ├─ 身份不是想出来的，是重复出来的。
 ├─ 每做一个 1% 的改进……
 └─ ……共 18 个叶子
```

这只是卡片墙换了个形状。节点数 ≈ 卡数，没有压缩。

### 错误形态：空心鸡汤（也不要做）

```text
原子习惯
 ├─ 成功的本质
 ├─ 改变命运
 └─ 作者启示
```

点开对不上任何原卡，还可能补出用户没划过的「目标设定理论」。

### 正确形态：默认画面只有概要

```text
                    原子习惯 · 我的划线
                              │
     ┌────────────┬───────────┼───────────┬────────────┐
     │            │           │           │            │
  身份由      复利只在     习惯四法则   先出现      环境在
  重复塑造      两年后       成对出现    再优化      替你做决定
   「5」        「2」         「4」       「3」        「4」
                              │
                    ┌─────────┴─────────┐
                    │                   │
                 建立：叠在          戒除：把手机
                 旧习惯后             充电器换房间
```

画面上 **7 个节点**（5 个一级 + 2 个二级），不是 18 个。括号里的数字是证据张数。

节点文案对照：

| 节点 | 归纳句（上图） | 为什么不是截断 | 证据卡 |
|---|---|---|---|
| 身份由重复塑造 | 归纳了 1、2、3、14、17、18 的共同论点 | 没有直接用 #1 的原句当标题 | 1 2 3 14 17 18 |
| 复利只在两年后 | 单独抽出时间尺度，避免和身份混成一坨 | 不是 #4 全文 | 4，可再挂 3 |
| 习惯四法则成对出现 | 建立四法则和戒除四法则是镜像，用户自己的 #13 已经点破 | 没有把 #5 整句贴上 | 5 11 13，二级再拆 |
| └ 建立：叠在旧习惯后 | 把方法收成一句可执行的 | 用的是归纳，#7 的个人注提高权重 | 6 7 |
